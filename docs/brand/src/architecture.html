How AppArmorX works

AppArmorX
AT BUILD TIME · GRADLE

Your app

  • Kotlin or Java, any architecture
  • No SDK, no init calls
  • Source is never edited

com.apparmorx.security

  • Verifies the signed policy, derives your signer pin from the release config
  • Rewrites bytecode: guards in Activities, Services, Receivers
  • Reroutes SDK calls (clipboard, device ID, location, TLS) through the firewall
  • Embeds the runtime and native engines (arm64, x86_64)
  • Audits the manifest, verifies the packaged APK

Protected APK

  • HTML report
  • SARIF for code scanning
  • JSON coverage + digests
  • Build fails if protection is missing
ON THE DEVICE · RUNTIME

Dependency firewall

  • Third-party SDK reads clipboard, device ID, location
  • Gets nothing / a blank ID
  • Trust-all TLS verifier rejected

28 checks, 5 groups

  • Tamper · debugging · root
  • Hooking & injection (native, direct syscalls)
  • Environment
CLEARDETECTEDUNAVAILABLE
Unavailable is never treated as safe

Response

  • Observe
  • Warn
  • Block screen
  • Mirage delay

Your server

  • Signed JSON report
  • Offline queue
  • Opt-in, HTTPS only
